
# Day 15：关键词检索

## 1. 实现方案

使用 PostgreSQL STRPOS 实现可测试的关键词检索基线。

查询流程：

用户问题
→ 关键词提取
→ PostgreSQL 子串匹配
→ 统计命中关键词数量
→ 按匹配数量降序排序
→ 返回 Top-K 切片

接口：

POST /api/v1/retrieval/keyword-search

请求字段与 Day 14 语义检索一致。

## 2. 排序规则

每个不同的查询关键词在切片中命中时计 1 分。

matchedTerms 越大，排序越靠前。

分数相同时，按 document_id、chunk_index 排序，
保证相同数据下的排序具有稳定性。

该分数不是概率，也不是经过校准的相关性分数。

## 3. 适用场景

- 产品型号和模型名称
- 软件版本号
- 订单编号
- 错误码
- 英文技术术语
- 可以直接匹配的中文短语

## 4. 已知限制

1. 连续中文字符被视为一个关键词，不进行专业中文分词。
2. 查询中文短语时，原文需要包含对应的连续文本。
3. 使用子串匹配，部分词也可能命中更长的标识符。
4. 不理解同义词、语义关系或上下文。
5. 不使用 TF-IDF 或 BM25，匹配数量仅用于基础排序。
6. 当前实现没有为关键词查询建立专用索引，大规模数据下需要进一步优化。
7. 通用词可能产生较多候选，需要结合实际测试集分析。
