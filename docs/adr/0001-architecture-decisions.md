# ADR-0001：RAG 知识库问答系统架构决策

- 状态：Accepted（已确定当前方案）
- 日期：2026-10-21
- 适用范围：RAG 知识库问答系统 V1

## 1. 背景

本项目需要构建一个基于 Java 的企业级知识库问答系统，实现文档上传、解析、文本切片、向量化、检索、答案生成和引用校验。

项目需要具备可测试性、可维护性和可复现性，同时控制首版开发复杂度。

因此，需要确定后端框架、数据库、向量存储方案和大模型应用集成方案。

## 2. 决策一：使用 Spring Boot 构建后端服务

### 决策

采用 Java 17 和 Spring Boot 3.x。

### 原因

- 与现有 Java 后端开发经验衔接，降低学习成本。
- 提供依赖注入、REST API、参数校验和统一异常处理等基础能力。
- 能够与 Maven、JUnit 5 和 Docker 等工具配合。
- 适合构建具有清晰分层和自动化测试的后端应用。

### 影响

- 使用 Controller 接收 HTTP 请求。
- 使用应用服务组织业务流程。
- 使用 Repository 或其他数据访问组件操作数据库。
- 通过 JUnit 5 编写单元测试和集成测试。

## 3. 决策二：使用 PostgreSQL 和 Flyway 管理数据

### 决策

使用 PostgreSQL 存储文档元数据和文本片段，使用 Flyway 管理数据库结构变更。

### 原因

- PostgreSQL 可以同时存储结构化业务数据和文档相关元数据。
- 支持事务、约束和索引，便于维护文档与文本片段之间的关系。
- Flyway 可以通过版本化 SQL 文件记录数据库迁移历史。
- 使用 Docker Compose 可以降低本地开发环境的配置差异。

### 影响

- 使用数据库表保存文档信息和文本片段。
- 数据库结构变更通过新增 Flyway 迁移文件完成。
- 不直接修改已经执行过的历史迁移文件。
- 通过 Docker 卷持久化数据库数据。

## 4. 决策三：使用 pgvector 实现向量存储

### 决策

在 PostgreSQL 中引入 pgvector 扩展，保存文本片段的 Embedding 向量，并支持向量相似度检索。

### 原因

- 可以在现有 PostgreSQL 基础设施上增加向量检索能力。
- 减少首版独立部署另一套向量数据库的复杂度。
- 文档元数据、文本片段和向量可以在同一数据库体系内管理。
- 便于后续验证语义检索和混合检索的效果。

### 影响

- Embedding 的维度必须与向量字段的定义一致。
- 需要设计向量写入、查询和删除接口。
- 需要测试相似度排序、重复写入和维度错误。
- pgvector 的具体启用和向量字段迁移安排在 Day 13 实现。

## 5. 决策四：使用 LangChain4j 集成大模型能力

### 决策

选择 LangChain4j 作为 Java 大模型应用集成方案。

### 原因

- 提供面向 Java 应用的大模型集成能力。
- 有利于接入 Embedding 和大语言模型服务。
- 能够减少业务代码与特定模型供应商之间的直接耦合。
- 适合在现有 Spring Boot 工程中逐步引入 AI 能力。

### 影响

- 实际依赖版本以项目 pom.xml 和对应版本的官方文档为准。
- 通过独立接口隔离 Embedding 和 LLM 调用。
- 先实现 Fake adapter，使核心业务测试不依赖真实模型服务。
- 后续再接入真实模型，并处理超时、调用失败和配置问题。

## 6. 决策五：隔离业务逻辑与外部 AI 服务

### 决策

采用接口与适配器相结合的设计，将核心业务流程与外部模型调用分离。

### 原因

- 外部模型服务可能超时、限流或返回异常。
- 自动化测试不应依赖真实 API 的可用性。
- 未来更换模型供应商时，应尽量减少业务代码修改。

### 影响

- Embedding 使用独立服务接口。
- 答案生成使用独立接口。
- 测试环境使用 Fake adapter 提供可预测的结果。
- 真实模型调用通过适配器接入。

## 7. 决策六：控制首版架构复杂度

### 决策

首版优先实现清晰、可测试的单体应用，暂不引入不必要的分布式基础设施。

### 暂不采用的方案

- 不急于引入 Kafka、RabbitMQ 等消息队列。
- 不采用复杂的多 Agent 编排架构。
- 不单独部署向量数据库。
- 不在首版实现完整的企业级单点登录系统。
- 不为尚未验证的性能需求提前引入复杂架构。

### 原因

当前阶段的核心目标是验证 RAG 完整链路，包括文档处理、向量检索、答案生成、引用校验和权限隔离。

### 影响

- 优先保证核心功能正确、接口清晰、测试可重复。
- 后续根据实际性能、并发和可靠性需求决定是否扩展。
- 不将尚未实现的能力描述为已完成。

## 8. 总结

当前技术路线如下：

- 后端：Java 17、Spring Boot 3.x。
- 构建与测试：Maven、JUnit 5。
- 关系数据库：PostgreSQL。
- 数据库迁移：Flyway。
- 向量存储：pgvector。
- 大模型集成：LangChain4j。
- 本地环境：Docker Compose。
- 测试策略：Fake adapter、单元测试和集成测试。

上述决策服务于 RAG V1 的可实现性和可验证性。后续如需改变关键技术方案，应记录变更原因、替代方案和实际验证结果。
