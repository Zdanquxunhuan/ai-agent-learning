# RAG 项目核心流程图

本文档描述 RAG V1 的三个核心业务流程：文档上传、文档索引和知识库问答。

当前流程属于架构设计草图，后续将根据实际代码实现进行调整。

## 1. 文档上传流程

```mermaid
flowchart TD
    A[用户选择文件] --> B[DocumentController 接收请求]
    B --> C{文件校验是否通过}
    C -- 否 --> D[返回参数错误]
    C -- 是 --> E[生成 documentId]
    E --> F[计算 contentHash]
    F --> G[保存原始文件]
    G --> H[保存文档元数据]
    H --> I[状态设为 UPLOADED]
    I --> J[返回 documentId 和状态]
```

### 流程说明

1. 用户通过 HTTP 接口上传文件。
2. 服务端校验文件是否为空、类型是否合法以及大小是否超限。
3. 为文档生成唯一标识，并计算文件内容哈希。
4. 保存原始文件及文档元数据。
5. 将文档初始状态设置为 UPLOADED。
6. 返回文档标识和处理状态。

## 2. 文档索引流程

```mermaid
flowchart TD
    A[读取已登记文档] --> B[状态更新为 PROCESSING]
    B --> C[解析文档内容]
    C --> D{解析是否成功}
    D -- 否 --> X[记录失败原因]
    D -- 是 --> E[文本切片 Chunking]
    E --> F[生成文本 Embedding]
    F --> G[保存文本片段和向量]
    G --> H{索引是否成功}
    H -- 否 --> X
    H -- 是 --> I[状态更新为 READY]
    X --> J[状态更新为 FAILED]
```

### 流程说明

1. 读取已登记的文档。
2. 将文档状态更新为 PROCESSING。
3. 使用对应的解析器提取文本。
4. 将长文本切分为多个 Chunk。
5. 将文本片段转换为向量。
6. 保存文本片段、必要的来源元数据及对应向量。
7. 全部处理成功后，将文档状态更新为 READY。
8. 发生处理失败时，记录错误并将状态更新为 FAILED。

说明：Embedding 和向量存储将在后续 Day 12、Day 13 实现；这里先展示预期的完整索引流程。

## 3. 知识库问答流程

```mermaid
flowchart TD
    A[用户提交问题] --> B[校验问题参数]
    B --> C[识别当前用户身份]
    C --> D[生成问题 Embedding]
    D --> E[检索有权访问的文档片段]
    E --> F{是否有足够证据}
    F -- 否 --> G[返回拒答结果]
    F -- 是 --> H[构建问题与证据上下文]
    H --> I[调用大模型生成答案]
    I --> J[校验引用 ID]
    J --> K[返回答案和引用来源]
```

### 流程说明

1. 用户提交问题，服务端校验输入。
2. 获取当前用户的身份和访问权限。
3. 将问题转换为向量，并检索相关文档片段。
4. 检索阶段必须限制在用户有权访问的文档范围内。
5. 如果没有足够证据，返回明确的拒答结果。
6. 如果证据充分，将问题和检索片段交给大模型生成答案。
7. 服务端校验引用是否来自本次检索结果。
8. 返回答案及其引用来源。

## 4. 三个流程之间的关系

```mermaid
flowchart LR
    A[文档上传] --> B[文档索引]
    B --> C[知识库问答]
    B --> D[READY 状态]
    D --> C
```

文档上传负责接收和登记数据，文档索引负责将原始文档转换为可检索的数据，知识库问答负责利用检索证据回答用户问题。

只有完成索引并处于 READY 状态的文档，才应参与正常问答检索。
